Каскад пускает трафик протокола через другую ноду панели:

```text
клиент → нода A → нода B → интернет
```

Клиенты подключаются к ноде A, а сайты видят адрес ноды B. Так можно держать точку входа там, где её не блокируют, а выходить в нужной стране.

## Настроить

1. Откройте подключение на ноде A и в поле **Выход в интернет** выберите «Через ноду».
2. В поле **Нода выхода** выберите ноду B.
3. Сохраните.

Панель сама откроет на ноде B скрытый ретранслятор с отдельным ключом для каждой ноды-источника. Ретранслятор слушает TCP-порт: первый свободный из запасных (2053, 2083, 2087, 2096, 2443, 3443, 4443, 5443, 6443, 7443, 8443, 9443, 10443, 11443, 12443), а если все заняты, случайный от 30000 до 59999.

Трафик считается один раз, на первой ноде. WARP для каскада не нужен.

:::caution
Если нода выхода недоступна, трафик этого протокола не идёт напрямую, протокол просто не работает до её возвращения. Так адрес ноды A не засветится случайно.
:::

## Цепочки длиннее

Кнопка **Каскад** на карточке ноды показывает, через какие ноды она выпускает трафик, состояние проверки (какой адрес видят сайты) и состояние ретранслятора: слушает порт, порт занят или не запустился.

Там же поле **Куда выпускать трафик других нод**: напрямую, через WARP этой ноды или через ещё одну ноду. Так строятся цепочки из трёх и более серверов. Петли панель не сохранит, а протокол не может выбрать выходом собственную ноду.

## Правила каскада

**Настройки → Маршрутизация → Каскад нод** задаёт правила ноды: часть её трафика уходит через другую ноду, а остальное — как обычно (напрямую, через WARP или целиком через выбранную ноду). Например, на ноде входа весь трафик идёт напрямую, а `youtube.com` — через основную ноду:

```text
DOMAIN-SUFFIX,youtube.com → Нода 1
```

Правило состоит из трёх полей:

- **`match`** — что ловить, правило вида `TYPE,VALUE`: `DOMAIN-SUFFIX,example.com`, `DOMAIN-KEYWORD,example`, `DOMAIN,example.com`, `DOMAIN-REGEX,…`, `DST-PORT,25` или `DST-PORT,1000-2000`, `IP-CIDR,203.0.113.0/24`. На самой ноде геобазы нет, поэтому `GEOSITE`/`GEOIP` здесь не поддерживаются — пользуйтесь доменами.
- **`inbound_id`** — необязательное: если задано, правило действует лишь для этого подключения ноды; без него — для всех, включая служебный вход ретранслятора. `null`/отсутствие = любой слушатель.
- **`exit_node_id`** — куда отправлять: id другой ноды панели. Сама нода, петли и цепочки длиннее 8 переходов не сохраняются.

Весь набор редактируется как **один JSON-массив**, порядок в массиве — порядок правил; выигрывает **первое подходящее**. Рядом в панели — шпаргалка по id нод и протоколов. Пример:

```json
[
  { "match": "DOMAIN-SUFFIX,youtube.com", "exit_node_id": 1 },
  { "match": "DST-PORT,25", "inbound_id": 3, "exit_node_id": 2 }
]
```

Сохранение атомарно: если хоть одно правило не прошло проверку, весь список отклоняется, прежние правила остаются. Правило действует раньше, чем выход целиком у протокола: если у протокола выбран выход через ноду B, а правило отправляет `youtube.com` на ноду C, то YouTube пойдёт через C, а остальной трафик протокола — через B.

## Проверка каскада

Откройте **Проверить ноду** на ноде входа (A), см. [Ноды](/Hikari/nodes/nodes/#проверить-ноду). Панель проверяет путь вход → выход → интернет и показывает, где он обрывается:

- **нода выхода не отвечает**: откройте её карточку, у неё своя причина и подсказка;
- **ретранслятор на ноде выхода не запущен**: нода выхода не подняла его порт, смотрите проверку этой ноды;
- **вход не достаёт до порта ретранслятора на выходе** или **у выхода нет интернета**: порт закрыт файрволом хостера ноды выхода, или сервер выхода не выходит в интернет.

На самой ноде выхода, если через неё выходят другие, проверка показывает порт её ретранслятора.

## Если порт ретранслятора занят

Если порт ретранслятора заняла другая программа, он сам переезжает на свободный порт, когда включён переключатель «Менять порт, если его блокируют» (**Настройки → Основное → Автоподбор**). Когда ретранслятор не работает, приходит уведомление в Telegram. Это работает с нодами версии 0.5.0.2 и новее.
