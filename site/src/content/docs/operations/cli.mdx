---
title: Команда Hikari
description: Справочник по команде управления сервером Hikari.
---

Команда `hikari` без аргументов открывает меню в терминале: состояние, обновления, логи, доступ, сайты REALITY, ноды, бэкапы. Те же действия доступны командами. Сами команды на английском, запускаются от root.

## Сервер

| Команда | Что делает |
|---|---|
| `hikari status` | контейнеры, процессор и память, состояние панели, доступное обновление |
| `hikari doctor [--json]` | проверить сервер панели или ноды, у каждой строки подсказка, см. ниже. `--json` печатает отчёт в JSON без секретов |
| `hikari support <код> [--dry-run]` | отправить поддержке проверку, состояние и последние строки лога (секреты вырезаны) с кодом из вашего обращения, см. ниже |
| `hikari logs [panel\|node]` | логи в реальном времени, <kbd>Ctrl</kbd>+<kbd>C</kbd> останавливает |
| `hikari restart` | перезапустить контейнеры |
| `hikari support-access on\|off` | разрешить или запретить на этом сервере [доступ для поддержки](/Hikari/operations/support-access/); `off` действует, что бы ни было в панели |
| `hikari update [--check]` | обновить сейчас, сначала бэкап, при сбое откат. `--check` только проверяет |
| `hikari install [флаги]` | установка, на установленном сервере открывает меню |
| `hikari uninstall [-y]` | остановить и удалить команду, данные остаются в `/opt/mikan` |

`hikari doctor` работает на сервере панели и на сервере ноды. Проверяет Docker и контейнеры, что порты слушаются, правила ufw для порта API ноды, порта панели и портов протоколов, синхронизацию времени (`timedatectl` и заголовок Date от github.com, допуск 30 секунд), DNS, выход по HTTPS на github.com и ghcr.io (нужны для обновлений), диск (✗ меньше 500 МиБ, ! меньше 2 ГиБ) и память. На ноде ещё раз отправляет «приветствие» панели и печатает результат. Каждая строка помечена ✓, ! или ✗ и содержит подсказку; если есть ✗, команда завершается с ненулевым кодом. `hikari status` сам предложит `hikari doctor`, когда что-то не так. Это инструмент для случая, когда панель не может достучаться до ноды совсем. Тот же набор проверок для сервера панели есть в самой панели: кнопка «Проверить сервер» в **Настройки → Система**.

Панель запускает `hikari doctor` и `hikari restart` на своём сервере, а на сервере ноды через API ноды, без SSH: она пишет файл-заявку в свою папку данных, а юнит systemd (`hikari-doctor-request.path`, `hikari-restart-request.path`, их ставит установщик и `hikari update`) выполняет команду и возвращает отчёт. Серверу, установленному до 0.5.1.1, для этого нужен один `hikari update`. Логи панели и нод тоже видны в панели, токены, ключи, пароли и ссылки подписок в них вырезаны. Всё это собрано на странице [Диагностика](/Hikari/operations/diagnostics/).

`hikari support <код>` нужна, когда панель не работает или нода недоступна для панели. Возьмите код из своего обращения в поддержку и выполните команду от root: она соберёт тот же отчёт, что `hikari doctor --json`, вывод `hikari status` и последние 300 строк логов контейнеров, вырежет секреты и отправит один JSON в службу поддержки (`MIKAN_SUPPORT_URL` направит его в другое место). Секреты, ключи и сертификаты не читаются и не отправляются. `--dry-run` печатает, что было бы отправлено, и ничего не отправляет.

## Доступ

| Команда | Что делает |
|---|---|
| `hikari url` | ссылка на панель и логин |
| `hikari reset-password` | новый пароль администратора, все сессии и API-ключи отзываются |
| `hikari reset-path` | новая секретная ссылка, старая перестаёт работать |
| `hikari disable-2fa` | выключить 2FA, если потерян телефон |

## Бэкапы

| Команда | Что делает |
|---|---|
| `hikari backup` | бэкап в `/opt/mikan/backups` |
| `hikari restore FILE [-y] [--no-db-snapshot]` | восстановить из бэкапа, см. [Бэкапы](/Hikari/operations/backups/) |

## Ноды и подключения

| Команда | Что делает |
|---|---|
| `hikari node list` | ноды панели |
| `hikari node add --name NAME --host IP [--domain D] [--api-port P]` | добавить ноду и получить ключ |
| `hikari node key NODE` | новый ключ ноды, старый перестаёт работать |
| `hikari node set NODE [--name] [--host] [--domain] [--enabled=true\|false]` | изменить ноду |
| `hikari join [KEY] [--panel-ip IP]` | на ноде: принять новый ключ из панели |
| `hikari inbound list` | подключения |
| `hikari inbound add PRESET [--port PORT] [--node N]` | добавить подключение, без пресета покажет список |
| `hikari inbound set NAME --port PORT [--node N]` | сменить порт, ключи и маскировка остаются |

Своя нода панели имеет номер 1, её адрес и домен меняются в настройках панели.

## Сертификаты

| Команда | Что делает |
|---|---|
| `hikari cert set --cert fullchain.pem --key privkey.pem [--node N]` | свой сертификат панели или ноды |
| `hikari cert show [--node N]` | что стоит сейчас |
| `hikari cert clear [--node N]` | вернуть автоматический сертификат (для ноды: самоподписанный) |
| `hikari cert proxy <домен>` | порт 80 держит nginx или Caddy: пропустить через него проверки центра сертификации к панели или ноде (правило с бэкапом, проверкой конфига и перезагрузкой) |

## Сайты маскировки REALITY

| Команда | Что делает |
|---|---|
| `hikari targets scan [--node N] [--json]` | найти подходящие сайты рядом с сервером |
| `hikari targets check --dest HOST:PORT [--sni NAME]` | проверить сайт |
| `hikari targets apply --dest HOST:PORT [--sni NAME] (--all \| --inbound NAME) [--force]` | поставить сайт всем подключениям или одному |

Для IP-адреса в `--dest` нужен `--sni`. Сайт проверяется перед применением, `--force` пропускает проверку.

## Адаптеры оплаты

| Команда | Что делает |
|---|---|
| `hikari addon list` | что работает и что есть в каталоге |
| `hikari addon install ID` | поставить или обновить адаптер |
| `hikari addon remove ID` | остановить и удалить, настройки и платежи в панели остаются |
